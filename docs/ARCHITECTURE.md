# Architecture

The game is a static Vite app. No server, official API, game account or secret is used.

## Battle simulation

`src/game/engine.ts` advances at a fixed 30 Hz. World coordinates span 18 × 32 tiles, with the blue player at the bottom. The river divides the battlefield at y=16. Ground units route through x=4 or x=14; flying units and the Hog Rider can cross directly.

Each player has an eight-card deck, a four-card hand, a four-card queue, capped elixir and crowns. Commands validate elixir and placement before mutating the hand or creating entities. Units acquire legal targets, move, attack and create projectiles. Spell and projectile damage resolve on impact. Buildings decay; the Witch summons skeletons; Prince charges; Balloon has death damage. The King Tower activates when damaged or after losing a Princess Tower.

AI uses the same command and resource path as the player. It scores affordable cards against visible threats, defends air with appropriate cards, and starts pushes when it has enough elixir. Training delays decisions. It does not receive extra elixir or deploy into illegal territory.

`src/game/opponents.ts` supplies six curated solo decks covering the full roster. Each has fewer than four spells/buildings, so a four-card hand always retains a troop to start a push. Classic and Double Elixir select with a seed hash outside the simulation RNG, excluding the most recent solo opponent in local history; unnamed legacy solo records map to Royal Trainer, and friendly records are skipped. Training retains the original deck. The UI passes a copied deck explicitly into `Battle`, preserving its legacy constructor default and recorded replay decks. Opponent name and optional `opponentType` metadata survive profile storage and progress backups, distinguish AI and friendly replay captions, and do not change reward calculations. Old records remain valid. AI deployment checks nearby legal tiles when a cycled card's preferred position remains occupied.

Freeze creates a persistent area instead of a projectile. At each fixed simulation step, enemy entities inside its three-tile radius receive enough stun to hold movement and attack through that step. The area persists for four seconds, catching late entrants and hidden Teslas, then releases them on the next step. Its source-derived rule table is pinned in `src/game/freeze-data.json`; the level-dependent increments of the archived game are outside this normalized roster. Active areas enter host snapshots as an optional field. The guest rotates their coordinates and team like other battlefield state, and recorded card commands recreate the same area during replay. Older snapshots without the field remain valid.

Poison uses the same persistent-area stream for eight seconds within a 3.5-tile radius. Its source-derived 250-ms hits refresh a one-second damage buff on enemies, including exposed buildings and Crown Towers but excluding buried Teslas. Each affected entity carries its remaining buff and one-second damage clock in simulation state, so leaving the circle still permits a final tick. Crown Towers receive 40% damage. The archived 57 damage per second is normalized to 121 for this roster using approximately the same ratio as its Fireball damage. Overlapping clouds refresh one status without stacking. The optional status, area hit cursor and rotated peer snapshot remain deterministic in replay.

Rocket adds a six-elixir fixed-target blast with archived speed 350/60, radius two and knockback 1.8. Its normalized damage is 1484 using the existing Fireball scale, with the archived 40% Crown Tower fraction stored only on Rocket projectiles. Other direct spells retain their 30% fallback, preserving historical replays. Native 60-frame pitch artwork uses a documented camera-space reconstruction. Trail envelopes repeat every 800 ms; particles retain their own source delays and anchor to the reconstructed projectile position at birth. Simulation-age cursors deduplicate repeated frames and recover active trails after a scene rebuild or late snapshot. `reference/client/rocket-reconstruction.json` separates source observations from the unverified native trajectory, pitch and shadow details.

Rage adds a six-second friendly area with a five-tile radius. Its 300-ms applications refresh a two-second status capped to the area's remaining lifetime. Overlaps retain the longest application without multiplying the boost. Living friendly troops, exposed buildings and Crown Towers qualify; hidden Tesla is excluded. Attack cooldown, pending windup, movement and Witch spawning advance at 1.35; deployment, stun, building decay, projectile travel and the existing Prince charge threshold retain real time. Optional buff and animation clocks survive peer snapshots and deterministic replay. Actor combat sounds use the source 1.25 pitch modifier; attack cues scheduled at attack creation use accelerated delays. The AI targets Rage at a valuable friendly push. Historical table flags supply these rules; `reference/client/rage-reconstruction.json` records the unverified native lifecycle details and reconstruction choices.

An initial seeded shuffle plus timestamped commands makes battles replayable. Replays disable AI decisions and consume the recorded commands. Particle randomness stays outside the simulation. Unit tests compare full entity, player and projectile state between a live run and its replay.

New battles use rules version 5, extending version-2 combat with Tesla concealment, delayed King activation and tower outcomes resolved at the end of a simulation step. Attack animations begin a pending windup; melee damage or projectile launch occurs when it completes. Target death, leaving attack range, stun and movable-unit knockback cancel that pending hit. Troops reconsider a distant tower destination when a defender or building enters sight, while retaining an engaged target. Projectile speed and homing are per-unit; Bomber throws retain their original landing position. Fireball travel time depends on distance and its radial knockback respects heavy-unit immunity. Arrows deliver three equal waves 0.2 seconds apart. Zap interrupts windups and Prince charge.

The original combat loop is frozen in `updateLegacyCombat()` for version-1 replay compatibility. A captured v1 match is compared against its original complete saved state. A captured version-2 match also retains its original complete state, including always-exposed Teslas. A captured version-3 match preserves immediate King activation. The captured version-4 match preserves delayed activation and the original immediate finish order. Current replay tests reproduce entire version-5 matches, pending attacks, projectile flight, Tesla exposure and King wake state. Profile history accepts all five versions and rejects unknown future versions.

Version 5 defers tower victory until every melee release and projectile impact in the 1/30-second simulation step has resolved. Both Kings falling in that step produces a draw; one fallen King takes priority over Princess Tower losses. Each defeated side's remaining Crown Towers receive death events without awarding extra crowns. Princess rewards are capped at three, and zero-value reward events are omitted. Equal tower trades at the regulation boundary or during overtime keep the battle running. Once a result is set, later steps and commands remain frozen. This simultaneous-impact window is this reconstruction's deterministic rule, not a measurement of Supercell's server timing. Earlier replay versions preserve their original scoring and finish order, including the historical same-step four-crown bug.

`scripts/import-combat.mjs` derives the compact `src/game/combat-data.json` table from pinned historical CSVs. Sight ranges, homing flags and knockback immunity are direct source fields. First-hit timing (`HitSpeed - LoadTime`) and the speed-to-tile conversion are reconstruction interpretations; damage, health and hit intervals remain this project's curated level-11 values. The implementation is deterministic, but is not a claim of exact original runtime behavior or current balance parity.

Tesla becomes untargetable and immune to damage while fully underground; lifetime decay continues. Ground units can pass over the closed hatch. Enemies within attack range trigger emergence, and departing enemies trigger an idle grace period followed by retraction. An exposed or partially exposed Tesla can take damage; stun freezes its transition. The 0.8-second rise, grace and retract intervals interpret the archived `UpTimeMs`/`HideTimeMs` values and native animation lengths. They are reconstruction choices, not measured original runtime behavior.

A King activates when it takes damage or loses a Princess Tower. Version-4 and later battles use the archived `KING_ACTIVATE_TIME_MS` value of 3,300 ms before starting its normal attack windup. Subsequent damage does not restart the wake sequence; stun overlaps the wake timer and still blocks attacks when present. Earlier replay versions keep immediate activation. `scripts/import-combat.mjs` derives this setting from the retained `globals.csv` alongside the combat profiles.

## Rendering

`src/render/arena.ts` projects the board with an orthographic Three.js camera. Static opaque geometry is batched by material. Animated source sprites share native textures, materials and lazily cached frame geometry. The importer preserves complete directional clips, child transforms and per-part color transforms. Sprites follow movement direction on bridges; attacks use full source sequences; Prince uses its separate charge animation and Balloon retains its multipart motion. Each Princess Tower uses its dedicated native Tower Princess character with both team colors and nine attack directions. It shares the animation library without adding a playable card to the roster; an Archer remains the asset-loading fallback. Camera-facing tower and scenery artwork keeps the original perspective. Locally constructed models remain available as asset-loading fallbacks.

Rendering interpolates positions independently of simulation steps. Health labels use the camera projection. Pointer coordinates are raycast onto the arena floor and passed to the same placement validator as AI commands. Preview ghosts use that validator, too.

Standing tower/building artwork is composited above opaque terrain without depth testing against the arena floor. Its authored pivot lies inside the image, so a normal billboard would otherwise lose its door, ramp or base below the floor. Transparent sprite sorting still uses the original arena position. Native buildings and static artwork fallbacks use the same rule, including placement previews.

Princess Towers reuse the King asset's native sheet and materials, with a separate geometry cache at their own world scale. Their base, attached character and foreground battlements share one billboard plane. Small depth offsets preserve the source layer order without drawing the foreground above unrelated arena objects. The dedicated Princess retains the original zero origin; its vertical placement uses `AttachedCharacterHeight` interpreted at 1,000 units per tile and projected through the arena camera. Static artwork remains the loading fallback. The additional geometry cache is disposed separately from shared textures/materials.

Deployment previews use the same `deploymentPositions()` formation as troop creation, including the complete 15-unit Skeleton Army and board-edge clamping. They share native animation geometry but own their translucent materials, keeping the actual troops opaque. Buildings use the loaded source artwork. Each lane's prohibited overlay follows its surviving Princess Tower, and the river stays blocked. Inline placement feedback combines territory and elixir checks, updates as elixir regenerates, and is announced as a polite status message. Dragged card portraits hide over the board so they do not cover the native formation. Pointer ownership prevents a second touch from changing an in-progress drag.

`src/render/effects.ts` reuses the native frame geometry and SC color-transform shader for 98 effect exports across two texture atlases. `src/render/projectiles.ts` draws source arrow, spear, cannonball, bomb and flame art along simulation flight positions, with trajectory-dependent billboard rotation and per-shot heights. Arrow waves are separate visible volleys. Tesla hit events retain the firing position so their authored beam joins the correct endpoints; Zap uses its native bolt, electricity and ground glow. Transient native effects follow a render effect clock that respects replay speed and pause and keeps advancing after victory so the final collapse settles. They share cached geometry/materials. Events retain their simulation time so effects start at the correct age when multiple steps precede a render; expired impacts are skipped. This rendering metadata does not change replay rules.

`src/render/spell-areas.ts` owns native ground and team-colored radius sprites for active Freeze and Poison areas. It advances the archived 30-FPS timelines from simulation age, so pause holds each pose and seeking or changing a battle releases old sprites. Snow and skull compositions use the shared particle pool and presentation clock. Poison repeats its three-second emitter plan at scheduled offsets from the cast event; negative ages preserve later cycles during delayed snapshots or replay seeks. A guest snapshot recreates the ground artwork from the optional area state without changing combat randomness.

`src/render/cold-filter.ts` follows stun state, applying the archived `filter_cold` colors at 60 FPS until the stun ends. `SpriteFilterStack` composes cold, deployment and Prince charge transforms into one actor-local material set for troops. Multipart native buildings and towers tint their base, foreground, turret and attached Tower Princess together, each with its own material clone. Expired layers restore their original materials; death and battle reset release all clones. The loop phase starts on first observed stun, a presentation approximation outside simulation and peer state. Static artwork fallbacks remain untinted.

`src/render/poison-filter.ts` adds the archived green `filter_poison` sequence to the same troop material stack and applies its small X/Y scale matrices after the source sprite resets its base size each frame. The 37-frame loop starts when the renderer first sees the buff; that presentation phase is not synchronized through peers. Multipart native buildings and towers compose Poison and Freeze color transforms across every source layer, including the attached Tower Princess. Only troop sprites apply Poison's source squash matrix.

`src/render/rage-filter.ts` adds the archived 50-frame, 30-FPS magenta pulse before Poison and Freeze in the material stack. Native buildings and all tower parts use that same timeline. Each renderer starts the tint phase on first observation, preserves it during pause and restores shared materials when the status ends. Ground/radius clips follow area age at 30 FPS and release with the area. The short Rage sparkle composition repeats at the area hit cadence; its source particle tails can outlive the area.

Balloon death-bomb projectiles use the native team export at its ground anchor: the clip contains its own drop and landing, so the renderer does not add the generic projectile height again. The source 31-frame animation runs once at 30 FPS within the existing 0.8-second combat lifetime. Existing hit events carry an optional `effect: "balloon-bomb"` hint; this adds no world event or simulation ID and survives the guest's coordinate rotation. The renderer replaces that hit's generic flash with the six native MegaBomb emitters, including the second-atlas ground mark. Late snapshots age the composition; pause holds it and seeking clears it. The existing particle budget, instancing and resource cleanup apply to both atlases. Read-only `projectileArtwork` and `destruction.clips` diagnostics expose rendered frames and active particle clips.

Fireball hit events select their native ten-component explosion through the card-to-spell-to-projectile binding. The 148-particle composition uses the same instancing, late-event aging, pause, replay seeking and 1,280-particle budget as death effects. Both perspectives preserve the hit card identity, and the seeded cosmetic plan consumes no combat RNG or simulation IDs. Missing native assets retain the previous generic impact fallback. Source layer interpretation and nested blend-group isolation remain presentation approximations.

Zap hit events select their 34-particle source composition, while Arrows selects its native ground mark. The 15 visible Arrows sprites are divided five per existing damage wave. A hit event carries the projectile ID and whether it uses the three-wave rules, so the renderer places the corresponding five marks without adding combat events, changing damage or consuming battle RNG. The same offsets are used for flight and impact; guest rotation flips them along with the board. An older hit event without this optional hint gets a single centered mark. Exact source scatter and Zap's screen-filter row remain visual approximations.

Musketeer, Bomber, Baby Dragon, Wizard and Cannon hit events select the `HitEffect` on their retained projectile row. Balloon and Tesla select their actor `DamageEffect` at the target point, where the source's ground debris or electrical spot is authored to appear. Namespaced `hit:` keys keep these impact compositions distinct from each card's death composition. Tesla still draws its source beam from the shooter to the target. Cards without supported native hit particles retain the generic fallback. All added particles use the existing event age, instanced batches, pause clock and replay reset path.

`src/render/buildings.ts` shares the native frame geometry and shader with troop sprites. Cannon chooses among 19 source aim angles per team and mirrors leftward shots. Tesla maps simulation exposure to the 39-frame source timeline using its authored deploy, idle, appear and hide labels. Its health bar follows the raised tower. The King uses its 98-frame activation timeline, separate 86/99-frame blue/red idle loops, and 36 half-turn cannon directions with leftward mirroring. Separate base, cannon and foreground meshes preserve source occlusion while allowing independent aiming. Wake frames follow the simulation countdown; replay seeking reconstructs the matching pose. Building previews share these assets; source textures and all frames are available offline.

Tower destruction is separate from combat state. `src/game/arena-layout.ts` supplies the same ordered six tower sites to the engine and renderer, preserving legacy IDs. Missing/dead towers produce the appropriate native rubble; rebuilding a replay renderer reconstructs ruins from current entities. Rubble is projected onto the arena floor with its authored screen proportions, avoiding billboard clipping below the floor.

`src/render/crowns.ts` uses the native 16-frame crown rotation for screen-space reward flights. Crown events include the newly earned count, so a direct King win produces three while a King destroyed after one Princess Tower produces two. This is presentation metadata and does not alter replay rules. Flights start from the projected tower position and end at the current DOM score counter. Their clock follows the other effects, including pause, replay speed and post-victory time. Positions and art bounds are recalculated on resize; expired effects and replay resets release their owned materials while preserving shared native geometry. The result panel waits 1.4 seconds of rendered effect time for the last crown. Its pending presentation is bound to the completed battle and is consumed by the frame loop, so backgrounding freezes the entire ending sequence and changing battles cancels the old presentation.

`src/render/destruction.ts` uses 24 retained death compositions, 13 impact compositions, one Cannon launch composition, two movement compositions, one Prince charge composition, one Hog Rider landing composition, 21 deployment compositions and 83 emitters. Tower collapses contain 78 particles; troop compositions preserve distinct elixir bursts, dust, clouds, ground marks and the Knight's lingering sword. Recursive source effects retain delays, team substitutions, component scale and renderable scale. A separate seeded cosmetic RNG preserves variety without changing the simulation.

`NativeDeploymentEffects` consumes the existing per-entity spawn lifecycle events through its own cursor. Each event optionally carries an immutable birth `origin`; peer projection rotates it with the board. This is presentation metadata and consumes no new world IDs, RNG draws or simulation actions. A late event ages its native composition at that origin even if the actor has moved or died. Older hosts may omit the origin; only a still-deploying entity supplies a safe positional fallback. Source-empty particle compositions stay empty. Card-level generic puffs remain only as a missing-native-asset fallback.

`NativeLaunchEffects` consumes Cannon launch audio events through a separate cursor. Launch cues now carry an immutable firing origin, rotated in guest snapshots; older cues without it simply omit the muzzle visual. The source composition renders 26 particles at the Cannon's firing height and ages them to the received snapshot time. Replay seek and battle replacement reset the cursor, preventing historical bursts from firing again. The added cue position does not affect combat rules or event IDs.

`NativeMovementEffects` compares successive Knight and Prince positions already present in the rendered battle state. It emits their shared three-fragment ground effect every 0.75 traveled tiles, interpolating within a coalesced frame and preserving partial distance across unchanged display frames. The 0.75-tile spacing is a browser reconstruction; the source animation marker timing has not been traced. Stopped units, deploy waits, teleports and replay resets do not leave delayed tracks. The feature adds no simulation events or peer fields.

The same visual tracker emits Prince's retained 12-particle `ChargeEffect=prince_charge` dust when his existing movement timer crosses 2.3 seconds, the threshold that switches his run animation and combat speed. It interpolates the crossing position and ages coalesced peer frames. Attack resets permit a later charge, and replay seeks clear the tracker. This is a cosmetic addition with no combat event or peer field.

The `effect_charge` marker uses a separate, source-backed dynamic text timeline: 43 matrices and alpha values at 30 FPS, with the archived Supercell Magic font and localized `TID_CHARGE` string. A DOM/SVG overlay follows the Prince through camera projection, freezes when match presentation pauses and releases after its source timeline or on seek/reset. It does not add to the particle atlas or affect battle state.

The same charge crossing applies the source `filter_protection` color sequence to Prince's native sprite. Its 54 frames at 60 FPS add a short yellow pulse and reduce blue slightly. A separate material for that actor composes the filter after the sprite's authored color transform; shared sprite geometry and other actors remain untouched. The material is restored when the 0.9-second source timeline ends, the actor dies, or a replay is reset. The source tables and frames establish the timing and colors; applying those color transforms to the charged actor is a reconstruction of the archived `Filter` binding rather than a traced native Filter renderer.

`hogJumpHeight` lifts only Hog Rider's sprite and health display across the river, leaving the team ring and ground shadow on the floor. The 2.2-unit sine arc is derived from river position, so pause, replay seeking and guest snapshots reconstruct the same pose without a new combat field. `NativeHogLandings` watches each rider cross the far bank and emits the pinned 70-particle `hog_rider_landing` composition at an interpolated landing point. New scenes and replay seeks clear its position history. The source provides jump and landing fields, but exact original airborne timing and height remain untraced.

The renderer shares the existing particle pool, source geometry, pause clock and cleanup across deployment, impact and death effects. Reset/seek consumes the current lifecycle history without replaying historical puffs. Medium bursts schedule 83 particles per entity and large bursts 133, after 300 ms. Two Archers therefore produce independent bursts. Source Ground-layer rocks keep their vertical motion, while planar ground dust/shadows retain floor placement; frame/layer/ground-mode batch keys keep their distinct depth materials separate.

`src/game/death-audio.ts` schedules the corresponding native sound groups from the same death events. Delays use match time, so replay speed and pause preserve their position relative to the death. Reset, seek, navigation, background suspension, mute and match completion discard pending cues. Stale network events and delayed cues older than half a second are skipped. `GameAudio` applies source pitch and per-group concurrent voice limits, releasing reservations on completion, media failure or stop. A friendly-match pause also stops active effects. Replays viewed from the guest side retain their original seed in the rendered battle, keeping sound and particle variation stable across repeated seeks. These audio decisions do not mutate the battle RNG or replay format.

`src/game/combat-audio.ts` separately schedules windup, launch, impact and spell-cast cues. The simulation retains a bounded 256-entry presentation stream with its own sequence, independent of entity/projectile/event IDs and the battle RNG. Pending attacks carry a cancellation token; projectile sound profiles survive their owner's death. Attack snapshots carry only the last second of events, retaining overlap for deduplication while omitting history already too old to play. Guest presentation swaps team colors without changing sound identity. Old snapshots without the optional stream remain valid. Existing version-1 through version-4 simulation outputs remain unchanged.

The scheduler chooses one archived variation per sound group, retaining duplicate rows as weights and source pitch/gain/delay ranges. Pending windup cues are removed on cancellation; stale cues, skipped history and navigation are discarded. `MaxRepeatMs` is interpreted as a minimum match-time interval per sound group. This and the mapping from effect fields to attack phases are reconstruction choices. Source priority and end padding remain metadata. Cosmetic selection uses the rendered battle's seed and the independent audio event ID; live peers may choose different variations. Repeated seeks within the same saved replay retain their choices.

The renderer also queues Prince's retained charge voice from the cosmetic charge crossing, using match time and the same native sound planner. Stale crossings are dropped, and pause/seek discard pending cues. It uses no simulation event ID or network field.

For slow display frames, the movement tracker accepts a bounded multi-frame charge crossing separately from its stricter footstep gate. A visible charge marker may begin late, so the voice is scheduled at the first observed frame and flushed alongside that marker; crossings older than the 43-frame marker are discarded. Teleports and replay seeks retain their guards.

Prince's double-damage contact emits a separate `impact-special` presentation cue from the archived `DamageEffectSpecial` branch. Ordinary hits retain `impact`; the new cue rides the optional presentation stream so peers and replay hear the same charged strike while older clients can ignore it.

The same stream now includes entity spawn, summoning, appearance, hiding and death notices. Card casting occurs once per accepted card, troop spawn cues once per created entity, and Witch summoning once per burst. Tesla appearance/hiding cues occur once when the transition starts, including a reversal. Spawn/summon/appearance/hiding cues retain an owner ID; death removes their pending voices without cancelling projectiles that are still flying. The scheduler also checks current living entities before releasing owned cues, covering coalesced network updates that skipped an older death event. Attack cancellation alone leaves deployment voices intact.

Snapshots put the new phases in an optional `lifecycleAudioEvents` field so older clients never feed unknown phases into their original sound planner. Current clients rotate both fields and merge them in audio-ID order before scheduling. Attack/cast history retains one second; the infrequent lifecycle field retains four seconds. Live snapshots feed audio immediately before another snapshot or graphics frame can replace them. A spawn cue arriving between half a second and four seconds late rebases its whole composition to the received match time, preserving follow-up spacing; current actor liveness still guards playback. All other cues retain the half-second stale limit. Balloon bomb creation and impact also use this optional field. They have no living-owner guard, because the source Balloon is already dead. Current planners ignore unknown future phases. No simulation IDs, combat RNG, replay schema or game rules change.

Particles are grouped by native frame and render layer into instanced meshes. Each geometry retains ordered texture/blend material groups: normal, multiply, screen and additive. Multiply/screen use premultiplied source alpha, while source additive glows brighten the arena. Each instance retains its own transform and fade opacity through an extension of the SC shader; native frame geometry and textures remain shared and intact. Instances sort back-to-front within a batch. Ground marks project onto the arena floor while other particles face the camera. The 1,280-particle cap bounds simultaneous effects while retaining all 1,028 scheduled particles from 60 Skeleton deaths and two native Zap impacts. The frame-geometry pool evicts unused batches above 96 entries and releases all batches at rest; clear/reset also disposes the owned materials. Swarm rendering uses bounded native particle draw calls instead of one draw per particle; this does not measure physical phone frame rate.

Nine source emitters add age-delayed particle tails. The renderer projects current/delayed endpoints into the camera plane, places the export origin at their midpoint and stretches the parent affine by `(renderedHeight + projectedDistance) / renderedHeight`. Child emission rotation remains a separate right-hand matrix factor, preserving the native nonuniform composition. Each particle caches its rotated frame bounds until that frame changes. A separate cosmetic stream samples millisecond delays without changing earlier particle choices. Read-only `destruction.tails` diagnostics report active/stretched counts and maximum stretch; no simulation or wire format changes are needed.

The arena advances the effect clock before consuming events, then uploads all particles after those events and before drawing. Newly created impacts and deaths therefore appear in that same rendered frame. This also prevents paused diagnostics from reporting new particle counts with the previous frame's draw buffers.

Paused updates reuse existing instance buffers when no particles were added and the camera orientation is unchanged. New bursts and camera rotation invalidate that cache even with zero elapsed time. Empty scenes still advance the effect clock without rebuilding particle groups.

Particle trajectories evaluate native linear horizontal deceleration and current-age gravity from retained static evidence. Nonzero inertia uses a closed sum of 16-ms steps; zero inertia uses the continuous vertical limit, so late snapshots and replay speed require no render history. Ground settling, air height and world scaling remain reconstruction choices. Transparency sorting across different frame batches is approximate. Reset/replay seeking clears transient particles. Finished matches stop producing projectile trails and allow the last impacts/debris to expire.

## Interface and persistence

`src/ui/connection.ts` plays the retained `bad_connection` clip during a local battle transport outage. The icon is decorative and does not intercept pointers; a separate polite text status remains usable if artwork fails. Opponent-only loss does not display a local outage icon. Frame changes follow foreground presentation time, reduced motion holds frame zero, and navigation/background suspension clears its presentation clock.

`src/main.ts` owns lobby, deck editing, battle controls, results and replay views. During battles, a viewport-height flex layout gives the arena all remaining space after the header and hand; short landscape screens use a two-column arena/hand layout. Safe-area insets, dynamic viewport height and touch targets support phone use without scrolling the match. Card hand elements update only after the hand changes. Health, timer and elixir update at about 10 Hz. AI battles and replays automatically pause when the page is hidden or enters page-cache suspension. Direct friendly battles pause when either browser is hidden or disconnected. The animation-frame loop is cancelled while hidden and restarted with a fresh timing baseline on return; the match remains paused until the player resumes. Lobby, paused and finished views render at 30 FPS, while active matches follow the display refresh rate. Troop animations and scenery use the match clock during battles/replays, so pause and replay speed affect them consistently. The FPS diagnostic reports frames actually rendered over a sampling interval. Modal dialogs pause a live AI match and resume when dismissed; friendly battle menus keep the browser-hosted match running while both tabs remain visible.

Battle keyboard shortcuts respect consumed events and browser modifier keys. Number selection, Escape cancellation and arena Space pause ignore auto-repeat so one held key cannot repeatedly toggle the state. Focused buttons and links retain their native keyboard behavior, including Space activation of replay speed, pause/resume, restart, Exit and King emote buttons. Modal inputs and the replay range retain their own keyboard handling. Escape closes the emote selector through its existing event owner before the global handler can pause the match.

`src/game/profile.ts` validates versioned localStorage data and recovers from corrupt or unavailable storage. It retains three decks, results for ten matches, trophy/gold counters, audio preferences and four chest slots. Card levels are normalized to level 11; progression does not alter battle stats.

Progress backups wrap that same profile in a versioned `browser-royale-progress` JSON envelope. Export creates a local download; import checks a two-megabyte byte limit, format version and every profile field through the storage decoder. An import must round-trip all known fields without normalization or discarded history, so an incomplete file cannot silently reset rewards or remove replays. Parsing writes no storage. The lobby settings preview the imported player and totals before applying the profile, audio and emote preferences together. Restore is unavailable during battles and replays. Local storage recovery remains tolerant, dropping invalid fields and individual replay records while retaining usable progress.

The generated service worker precaches each release independently and serves its matching HTML shell and assets together. A new worker waits instead of taking over active clients and deleting their assets. `OfflineUpdates` offers activation only from an idle lobby, and rechecks availability when clicked. The worker checks all same-scope window clients before accepting that request; another arena tab blocks activation. Windows outside the registration scope and unrelated caches are excluded. During an accepted update, the app is inert until controller change reloads it onto the complete new cache. Closing all clients also permits the browser's ordinary activation lifecycle. Registration failures leave the game playable and can retry on a later visit.

`src/ui/announcements.ts` selects native announcement frames directly from simulation time. A cached signature avoids DOM changes while paused; seeking resets the previous clock and restores the correct frame without replaying skipped cues. SVG text uses the archived Supercell Magic font and retained source transforms/colors; the elixir icon uses the cropped native texture. Responsive bounds keep the overlay inside the arena in portrait and landscape. A regulation winner at exactly 180 seconds leaves the clock at zero and suppresses overtime; tied battles enter the two-minute overtime sequence. Existing replay rules remain unchanged.

Countdown voices are emitted once when a displayed second crosses 10 through 1. The overtime jingle follows the 180-second boundary; discontinuities larger than half a second are silent. The simulation already caps each rendered update at 15 fixed steps. `GameAudio` tracks active sound instances, removes ended/rejected playback, updates playback rates with replay speed, and stops effects on pause, mute, backgrounding or navigation. Match start/end horns use source sound mappings. Result music begins with the result panel after the final crown animation.

`src/ui/intro.ts` owns a separate presentation clock for the 134-frame, 30-FPS native battle opening. Frame 103 is the retained `actionFrame` label: before it, the clock consumes elapsed presentation time and hands zero time to the simulation. When an update crosses that boundary, only the remainder advances combat. The first 3.433 seconds therefore consume no match time, elixir regeneration or AI decisions. The last 31 frames can overlap active play. Pausing/backgrounding freezes this clock; replay speed scales it. Seeking clears the intro, and replay restart creates a new opening without changing replay data or rules versions. Near-boundary floating-point values snap to the exact authored times so fixed-step updates release combat on frame 103.

`src/ui/native.ts` shares SVG text, polygon, texture and color-transform rendering between announcements and introductions. Each multipart ribbon retains its own polygon layers; constant-UV polygons sample their source color instead of attempting a singular affine transform. ## Solo damage-spell decisions

`src/game/spell-targeting.ts` evaluates Fireball, Arrows, Zap and Rocket against visible, living enemy troops, exposed buildings and Crown Towers. Body positions and nearby pair midpoints supply legal candidate centers. Value reflects effective damage and removal per body, with a small defensive preference; swarm cost is divided by the card's spawn count. A dormant King incurs an activation penalty. A lethal King takes priority over a Princess, and cheaper spells receive preference for the same finishing opportunity. Thresholds are browser AI heuristics, not native-client rules.

Friendly spell projectiles reserve damage at their fixed destination, including delayed Arrows waves and Rocket's distinct Crown Tower fraction. This prevents repeat finishers while a lethal blast is in flight. The planner reads current positions without forecasting movement, so moving troops can evade long flights. It consumes no random draws or mutable state. Battle retains one seeded preference draw per affordable card and its existing decision cadence; only a worthwhile spell target bypasses the usual six-elixir opening wait. Recorded commands preserve the result without rerunning the AI during replay. `src/game/area-spell-targeting.ts` handles the persistent spells through the same legal center candidates. Rage values deployed advancing troops and engaged defenses, divides swarm cost per body and discounts wounded friends. It waits for useful movement or fighting, excludes idle Kings and hidden Tesla, and avoids refreshing a covered group, an existing boost or a group held by enemy Freeze. A worthwhile Rage can bypass the six-elixir opening wait.

Freeze requires nearby friendly support able to benefit from the control. It aggregates friendly swarm support, checks both combat ranges and the defender's ability to hit that support, and excludes enemies already held by a friendly Freeze. Hidden Tesla remains eligible, matching the spell's targeting rule; a dormant King is not a useful defender to freeze.

Poison projects the full duration against stationary buildings/towers and uses a shorter, explicitly heuristic dwell estimate for troops. It excludes buried Tesla and enemies covered by an existing cloud. A new cloud does not add its damage to the overlapping cloud's budget, since the status does not stack. Direct spells conservatively reserve remaining whole seconds of friendly Poison damage against stationary targets, using the longest overlapping cloud. This can underestimate a partial final tick or a lingering buff; it avoids claiming exact future movement or status timing. Projected Poison finishers prefer a faster direct spell at equal cost. All decision code remains outside recorded replay playback.

## Browser-to-browser friendly battles

The default session uses `PeerRoomClient`, an ordered WebRTC data channel and a manual offer/reply exchange. SDP and gathered ICE candidates travel in a versioned token or URL fragment. A public STUN endpoint helps discover direct routes; there is no signaling backend or TURN relay. Some remote networks cannot establish a direct route. No microphone or camera is requested.

`peer-host-worker.ts` runs `PeerMatch` in the inviting browser at 30 Hz with a bounded fixed-step accumulator. It validates both teams' commands, produces masked snapshots at about 15 Hz and delivers canonical reaction events. One in-flight snapshot and the latest pending snapshot are retained per perspective. The UI sends a pulse; an unresponsive host UI, hidden player or disconnected peer pauses the shared simulation. This does not survive host reloads. Surrender uses the same replay record and result presentation as other matches.

Data packets are bounded and chunked below phone data-channel message limits, with ordered assembly and backpressure control. Invite tokens validate version, role, room identity and mode before setting a remote description. Host messages determine battle state, so a modified host can cheat; this is a friendly mode, not a trusted ranked service. See `MULTIPLAYER.md` for the exchange and connectivity limits.

## Retained server regression path

The following older transport is selected only with `VITE_LEGACY_ROOMS=1`; the normal dev server, build and preview do not attach it.

`server/rooms.ts` attaches the `/battle` WebSocket endpoint to either Vite's development server or the production HTTP server. Each room owns a 30-Hz `Battle` with AI disabled. Both ready checks start the same native intro countdown. Room membership selects a player's team; submitted cards are resolved against the server hand and normal deployment rules. The client cannot submit a clock, damage or elixir value. Snapshots are sent at 15 Hz and after accepted moves, with opponent hand/queue/elixir masked until the final replay. Input sequences prevent duplicate spends.

`src/network/client.ts` exposes the room API and persists reconnect credentials in session storage. `src/network/transport-worker.ts` owns the same-origin WebSocket, native ping/pong handling, application heartbeats and bounded retries through `client-core.ts`, with timers separated from graphics work on the UI thread. WebKit can still route worker socket callbacks through that thread. A three-second UI pulse identifies a blocked delivery path: application ping/check callbacks wait until the UI resumes, then allow one delivery turn for queued messages. This avoids false quiet-connection closes and queued ping bursts; responsive clients retain the 15-second quiet deadline, and server native heartbeats and reconnect grace are unchanged. Each connection generation rejects stale worker messages. State delivery permits one in-flight snapshot and retains only the latest pending snapshot until the UI acknowledges receipt; room, welcome, error and reaction messages remain ordered and are not coalesced. Worker creation/load failures fall back to the direct client, reusing the reserved seat from memory even when storage is unavailable. That fallback does not provide protection from a blocked UI thread. Reloading the same tab automatically resumes its saved room unless the URL explicitly invites the player to a different room. `src/network/perspective.ts` rotates red's coordinates and swaps presentation colors without altering canonical server commands. This includes projectile destinations/origins, troop positions, event positions and tower lanes. Replay metadata records the viewing team; a red replay runs the original canonical engine and projects its state into the rendered battle. No combat rules version change is needed.

`src/bootstrap.ts` and `src/network/session.ts` restore a saved connection before importing the graphics-heavy main module. Startup waits for welcome/error or an eight-second connection fallback, buffering only the latest room, snapshot and error. The main view then takes over the same client and consumes those messages; its initial lobby reset preserves the reserved seat. Fatal errors discard buffered state so an expired session cannot initialize a stale battle. Failed graphics downloads offer a reload action, and service-worker registration handles a main module that finishes after the document load event.

Client heartbeats distinguish a quiet server from a delayed browser event loop. If the heartbeat callback itself was delayed, queued socket messages get one interval to run before liveness is judged again. A normally running but silent connection still closes after the original message deadline; a stalled, still-silent connection closes at the next ordinary heartbeat. Server reconnect grace and authoritative match timing are unchanged.

Vite's JavaScript module preloads are disabled so a failed graphics download can recover on reload in affected WebKit builds ([WebKit 270357](https://bugs.webkit.org/show_bug.cgi?id=270357)). The tiny entry imports the session client normally, and then dynamically imports the main view. Vite still loads the view's CSS before running it. The browser regression exercises the built server so this bundling behavior is covered.

Online menus do not pause the simulation, and the server continues while a browser is backgrounded. Lost connections receive 30 seconds to resume; explicit surrender/leave and timeout resolve on the server. Friendly records keep the opponent name and room identity, suppress ranked rewards and deduplicate reconnects to a finished match. Room state is ephemeral and single-process. Deployment, lifecycle and validation details are in `MULTIPLAYER.md`.
