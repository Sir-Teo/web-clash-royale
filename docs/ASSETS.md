# Asset provenance

Card illustrations, character renders, arena thumbnails and audio are imported from [RoyaleAPI/cr-api-assets](https://github.com/RoyaleAPI/cr-api-assets), a public fan resource. Original game artwork/audio and Clash Royale trademarks belong to Supercell. The import script records an exact upstream commit and hashes in `public/assets/manifest.json`.

Original in-game shapes and animation export metadata are imported from [smlbiobot/cr](https://github.com/smlbiobot/cr) at commit `7fc7687e6de74690e902543ee4b59f562121e225`. These are archived Clash Royale 1.8.1 assets; the Wizard and Goblin Stadium scenery use 1.8.0. They are historical assets, not the current game client. Source metadata is retained in `reference/sc/`; metadata and lossless texture hashes are in `public/assets/animations/manifest.json`.

`scripts/import-sprites.mjs` uses the shared bounded SC1 reader in `scripts/lib/sc.mjs`. It preserves full walk, idle, attack and Prince charge sequences at their native 24–30 fps, nine source directions with left-facing mirroring, nested display-list transforms, source UV polygons and color transforms. Balloon uses its full multipart sequences with a single facing. Skeleton art is shared between teams; other families retain distinct team exports. Baby Dragon exports are explicitly selected because its source file also contains Inferno Dragon art. Native source textures are bundled as lossless WebP. Geometry is reconstructed and cached per unique frame in the browser; no four-frame sampling or fixed 128-pixel cells remain. The native SC color transform layout is documented in [SupercellFlash](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/transform/ColorTransform.cpp).

`scripts/compose-scene.mjs` reconstructs first-frame display lists, resolves child clips and transform matrices, triangulates source UV polygons and produces tower and scenery textures. The format reference is [Galaxy1036/sc_decode](https://github.com/Galaxy1036/sc_decode/blob/master/sc_decode.py). Scaling is 1/1024 for matrix coefficients and 1/20 for vertex/translation coordinates. The retained per-export JSON files record bounds, origins and triangle counts. This is static asset reconstruction; no original game executable was run, and it does not establish original runtime behavior.

`reference/goblin-arena.csv` retains the historical 1.8.0 `assets/locations/goblin_arena.csv` placement table from the same archive commit. It was decoded as LZMA with the archived four-byte length field expanded to the standard eight-byte field. Stadium decorations use those coordinates at 1,000 coordinate units per tile. The renderer uses a 30-pixel art scale per tile; this display scale is a reconstruction choice.

The surrounding 3D geometry, fallback troop models, particle renderer, interface implementation and simulation code are created for this project. Native particles and battle announcements come from the archived sources described below. Lilita One and Nunito Sans are bundled via Fontsource (OFL). The native Supercell Magic font is a separate original game asset belonging to Supercell; the OFL attribution does not cover it.

Original projectile/electrical/impact exports are retained from the same 1.8.0 archive's `assets/sc/effects` and `effects_tex.png`. `reference/sc/effects.bin` stores the source metadata; `scripts/import-effects.mjs` reconstructs 45 selected exports, preserving their source parts, UV polygons and color transforms. `public/assets/effects/manifest.json` records source, metadata, output and texture hashes. The arrow, spear and Fireball orientation sequences are not played as looping animations: selected side-view source frames are rotated to the projected flight tangent. Dragon flames, Wizard fire, Tesla beams and Zap bolts retain authored animation frames. Native-to-world scaling, projectile heights, arcs, trail particles and effect placement are reconstruction choices. The original effects sheet is bundled as lossless WebP.

Rules reference: [Supercell's November 2019 update](https://supercell.com/en/games/clashroyale/blog/release-notes/november-update/) documents three-minute regulation, two-minute overtime and triple elixir in the last overtime minute. This game implements a classic eight-card format with normalized, curated card stats; it does not claim live balance parity.

Combat tables are retained in `reference/logic/` from the same pinned archive, under `apk/1.8.0/com.supercell.clashroyale_1.8.0_unpack/assets/csv_logic/`. The source filenames are `characters.decoded.csv`, `buildings.decoded.csv`, `projectiles.decoded.csv` and `spells_other.decoded.csv`. `manifest.json` records their SHA-256 hashes. Run `npm run assets:combat` to regenerate the 23 runtime combat profiles. The archived `SightRange`, `Homing`, `IgnorePushback` and projectile `Speed`/`Gravity` fields guide combat behavior. Millisecond timing, 1,000 distance units per tile and 60 speed units per tile/second are interpreted into browser simulation units; `HitSpeed - LoadTime` supplies inferred windup timing, capped at the curated attack interval. These are documented reconstruction choices rather than verified proprietary runtime semantics. The three-wave Arrows sequence over 0.4 seconds is documented in the official November update linked above.

Defensive buildings use both team exports from the pinned 1.8.1 `building_basic_cannon` and `building_tesla` files. `scripts/import-buildings.mjs` retains 19 Cannon aim frames and 39 Tesla frames per team, including the authored `deploy`, `idle`, `appear_start`, `appear_end`, `hide_start` and `hide_end` labels. Frame-label parsing follows [SupercellFlash MovieClipFrame](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/display_object/MovieClipFrame.cpp). `public/assets/buildings/manifest.json` records source, output and texture hashes. The buried Tesla damage protection is described in [Supercell’s March 2020 balance notes](https://supercell.com/en/games/clashroyale/blog/release-notes/season-9-balance-changes-2/). The implemented roster has no Earthquake or Freeze; curated Tesla health/lifetime remain unchanged. The archived `UpTimeMs` and `HideTimeMs` fields are interpreted as 800-ms emergence, idle grace and retraction intervals, with partial transitions reversing continuously.

The King Tower comes from the same pinned 1.8.1 `building_tower` source. Both team exports contain 98 frames at 30 FPS with `idle: 0`, `start: 1` and `stop: 97`. The importer preserves the nested 86-frame blue and 99-frame red King idle clips. It splits the stopped display list around the 36-frame cannon child so the renderer can aim independently while preserving the source base/foreground order. Enlarged source-frame inspection confirms a half-turn sequence, mirrored for leftward aim. Both destroyed-ground exports are retained in the same asset. Hashes are included in the building manifest.

`reference/logic/globals.csv` is retained from the pinned 1.8.0 `globals.decoded.csv`. Its `KING_ACTIVATE_TIME_MS` value is 3,300; the importer writes this as `kingActivationSeconds` in `src/game/combat-settings.json`. The original wake sequence is used at native FPS, then the separate cannon directions track the current target. Earlier replay rules retain their original immediate activation. This combines historical assets with this project’s curated combat stats.

`reference/client/effects.csv` and `particle_emitters.csv` retain the pinned 1.8.0 client tables (`effects.decoded.csv` and `particle_emitters.decoded.csv`). `scripts/import-destruction.mjs` resolves 23 death compositions from the character/building `DeathEffect` fields, including TowerExplode/King_player_die. It retains 21 emitters with source particle counts, lifetime/interval ranges, delayed smoke, native exports, scales and fades. Nested effects accumulate delays and multiply `Scale`/`RenderableScale`; enemy substitutions are resolved for the red team. The manifest hashes both client tables, the character/building tables, the card-to-source mapping and generated output. Tower_destroyed_ground1 belongs to Princess Towers; ground2 belongs to Kings, as specified by those compositions. Bounds include every frame because some authored effects start with an empty display list.

Troop death imports add 13 exports from the same effects sheet: two elixir particles, purple glow, blue smoke, three ground splashes, four dust variants, the Knight sword and a destruction cloud. The Knight composition retains its 24–25-second sword lifetime; Prince adds dust, Giant has a larger burst, Skeleton uses smaller components and Balloon has its own airborne clouds. Sounds and non-particle rows in these compositions are not imported.

The same sheet supplies `crown_rotate_anim`: 16 frames at 30 FPS, preserving all eight unique authored rotation poses. Its retained ribbon is blue. A shader recolors only blue-dominant ribbon pixels for the red opponent while preserving the gold and neutral highlights; this palette adaptation and the flight path/timing are browser reconstruction choices. Source metadata, generated geometry and texture hashes remain recorded in the effects manifest.

Particle positions, speeds and gravity use 30 source pixels per world tile. Blank component times are interpreted as zero; intervals spread particles within emitter duration. Exponential drag interprets the source inertia value, and ballistic particles settle against the floor. These are browser reconstruction choices, not measured original-client particle physics. Camera shake and the source death sound are not implemented by this checkpoint.

The dedicated Tower Princess comes from the pinned 1.8.1 `chr_princess` metadata and `chr_princess_highres_tex.png`. The archived TowerPrincess character row explicitly selects `princess_tower`/`princess_tower_red`; the importer filters to these prefixes and excludes the deployable Princess clips. It preserves 54 directional clips (1,800 frame references, 1,016 unique frames), native 24 FPS, both team colors and the high-resolution texture as lossless WebP. Source/output/texture hashes are in the animation manifest. The dedicated character retains its authored zero origin instead of using the ground troops' image-derived anchor.

The building importer also retains `StarTower_base_blue/red` and `StarTower_top_blue/red` in the existing King asset, sharing its original texture sheet. The native foreground covers the Princess's lower body when it crosses the battlements. Source-coordinate alignment was checked against the corresponding base texture for both teams. `AttachedCharacterHeight: 2200` comes from the retained PrincessTower building row and is interpreted as 2.2 world units; the building manifest hashes this table alongside the binary metadata. Character size, world scaling and the camera projection remain reconstruction choices.

Battle announcement assets come from the same pinned 1.8.0 archive: `sc/ui`, `sc/ui_tex.png`, `font/supercell-magic_0.ttf`, `csv_client/texts.decoded.csv` and `csv_client/sounds.decoded.csv`. The binary metadata and both decoded tables are retained under `reference/`. `scripts/import-ui.mjs` preserves five 30-FPS exports: `print_endTimer` (357 frames), `print_30secondsLeft` (80), `print_60secondsLeft` (148), `print_60secondsLeft_overtime` (71) and `print_extra_time` (139). Thirteen original text styles retain their font, size, bounds, alignment, colors, outlines and per-frame matrices. Text-field parsing follows [SupercellFlash TextField](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/display_object/TextField.cpp). The elixir icon's polygon and UV coordinates are retained with a lossless cropped texture. Source/output hashes are recorded in `public/assets/ui/manifest.json`.

The countdown's first six numeric children contain repeated `TID_5` placeholders; the importer binds its ten successive numeric segments to 10 through 1. The archived `+60s` overtime text becomes `+120s` to match this game's two-minute overtime, and the last overtime minute reuses the elixir animation with `X3 Elixir`. Double-elixir mode uses the notice without a redundant X2 transition. The browser aligns numeric frames to displayed seconds. Trigger times, responsive placement, SVG text baseline/outline width and font rasterization are reconstruction choices. A least-squares affine transform fits the icon's independently quantized XY/UV vertices within 0.04 source display units, avoiding seams between SVG triangles; it is a small approximation to the source mesh.

The sounds table supplies the ten `Countdown_10` through `Countdown_1` voices, `sound_extra_time_jingle`, `match start` and `Gameend Horn`, including relative volume. Their matching OGG derivatives come from the pinned RoyaleAPI asset collection and are hashed in the main asset manifest. Native relative gains are scaled by a shared browser mix gain of 0.35. Cue scheduling and playback-rate changes use this game's clock and are not measurements of original audio-engine behavior.

`scripts/import-intro.mjs` uses that same pinned `sc/ui` metadata, atlas, text table and font to retain `pvp_battle_start` and `pvp_battle_start_training`. Each has 134 frames at 30 FPS and an `actionFrame` label at frame 103. The import retains eight text styles and eight source shapes, including the three-polygon red and blue ribbons, source shadows, glints, crossed swords and dimming rectangles. Twelve nonconstant texture polygons are cropped losslessly; the constant-UV dimming polygon retains its sampled source color. Polygon XY/UVs, display order, frame matrices and colors remain in the runtime data. Every crop, the generated timeline and the derived `src/ui/intro-settings.json` are hashed in `public/assets/ui/intro/manifest.json`.

Player name, guild labels and the arena title/number are runtime bindings. Visitor labels remain empty, and the retained league-badge placeholder is hidden because this game uses unranked Arena 1. Training uses the training intro export but still names the actual Goblin Stadium board. Text fitting, responsive scale/placement, cropped-polygon affine fitting (within 0.05 source display units), and interpreting `actionFrame` as the point that releases the browser simulation are reconstruction decisions. This is source-guided animation playback, not a measurement of the proprietary client's startup scheduling.
