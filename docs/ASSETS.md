# Asset provenance

Card illustrations, character renders, arena thumbnails and audio are imported from [RoyaleAPI/cr-api-assets](https://github.com/RoyaleAPI/cr-api-assets), a public fan resource. Original game artwork/audio and Clash Royale trademarks belong to Supercell. The import script records an exact upstream commit and hashes in `public/assets/manifest.json`.

Original in-game shapes and animation export metadata are imported from [smlbiobot/cr](https://github.com/smlbiobot/cr) at commit `7fc7687e6de74690e902543ee4b59f562121e225`. These are archived Clash Royale 1.8.1 assets; the Wizard and Goblin Stadium scenery use 1.8.0. They are historical assets, not the current game client. Source metadata is retained in `reference/sc/`; metadata and lossless texture hashes are in `public/assets/animations/manifest.json`.

`scripts/import-sprites.mjs` uses the shared bounded SC1 reader in `scripts/lib/sc.mjs`. It preserves full walk, idle, attack and Prince charge sequences at their native 24–30 fps, nine source directions with left-facing mirroring, nested display-list transforms, source UV polygons and color transforms. Balloon uses its full multipart sequences with a single facing. Skeleton art is shared between teams; other families retain distinct team exports. Baby Dragon exports are explicitly selected because its source file also contains Inferno Dragon art. Native source textures are bundled as lossless WebP. Geometry is reconstructed and cached per unique frame in the browser; no four-frame sampling or fixed 128-pixel cells remain. The native SC color transform layout is documented in [SupercellFlash](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/transform/ColorTransform.cpp).

`scripts/compose-scene.mjs` reconstructs first-frame display lists, resolves child clips and transform matrices, triangulates source UV polygons and produces tower and scenery textures. The format reference is [Galaxy1036/sc_decode](https://github.com/Galaxy1036/sc_decode/blob/master/sc_decode.py). Scaling is 1/1024 for matrix coefficients and 1/20 for vertex/translation coordinates. The retained per-export JSON files record bounds, origins and triangle counts. This is static asset reconstruction; no original game executable was run, and it does not establish original runtime behavior.

`reference/goblin-arena.csv` retains the historical 1.8.0 `assets/locations/goblin_arena.csv` placement table from the same archive commit. It was decoded as LZMA with the archived four-byte length field expanded to the standard eight-byte field. Stadium decorations use those coordinates at 1,000 coordinate units per tile. The renderer uses a 30-pixel art scale per tile; this display scale is a reconstruction choice.

The surrounding 3D geometry, fallback troop models, particle renderer, interface implementation and simulation code are created for this project. Native particles and battle announcements come from the archived sources described below. Lilita One and Nunito Sans are bundled via Fontsource (OFL). The native Supercell Magic font is a separate original game asset belonging to Supercell; the OFL attribution does not cover it.

Original projectile/electrical/impact exports are retained from the same 1.8.0 archive's `assets/sc/effects` and `effects_tex.png`. `reference/sc/effects.bin` stores the source metadata; `scripts/import-effects.mjs` reconstructs 60 selected exports from that sheet plus three from `building_mega_bomb`, preserving their source parts, UV polygons and color transforms. `public/assets/effects/manifest.json` records source, metadata, output and texture hashes. The arrow, spear and Fireball orientation sequences are not played as looping animations: selected side-view source frames are rotated to the projected flight tangent. Dragon flames, Wizard fire, Tesla beams and Zap bolts retain authored animation frames. Native-to-world scaling, projectile heights, arcs, trail particles and effect placement are reconstruction choices. The original effects sheet is bundled as lossless WebP.

Rules reference: [Supercell's November 2019 update](https://supercell.com/en/games/clashroyale/blog/release-notes/november-update/) documents three-minute regulation, two-minute overtime and triple elixir in the last overtime minute. This game implements a classic eight-card format with normalized, curated card stats; it does not claim live balance parity.

Combat tables are retained in `reference/logic/` from the same pinned archive, under `apk/1.8.0/com.supercell.clashroyale_1.8.0_unpack/assets/csv_logic/`. The source filenames are `characters.decoded.csv`, `buildings.decoded.csv`, `projectiles.decoded.csv` and `spells_other.decoded.csv`. `manifest.json` records their SHA-256 hashes. Run `npm run assets:combat` to regenerate the 23 runtime combat profiles. The archived `SightRange`, `Homing`, `IgnorePushback` and projectile `Speed`/`Gravity` fields guide combat behavior. Millisecond timing, 1,000 distance units per tile and 60 speed units per tile/second are interpreted into browser simulation units; `HitSpeed - LoadTime` supplies inferred windup timing, capped at the curated attack interval. These are documented reconstruction choices rather than verified proprietary runtime semantics. The three-wave Arrows sequence over 0.4 seconds is documented in the official November update linked above.

Defensive buildings use both team exports from the pinned 1.8.1 `building_basic_cannon` and `building_tesla` files. `scripts/import-buildings.mjs` retains 19 Cannon aim frames and 39 Tesla frames per team, including the authored `deploy`, `idle`, `appear_start`, `appear_end`, `hide_start` and `hide_end` labels. Frame-label parsing follows [SupercellFlash MovieClipFrame](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/display_object/MovieClipFrame.cpp). `public/assets/buildings/manifest.json` records source, output and texture hashes. The buried Tesla damage protection is described in [Supercell’s March 2020 balance notes](https://supercell.com/en/games/clashroyale/blog/release-notes/season-9-balance-changes-2/). The implemented roster has no Earthquake or Freeze; curated Tesla health/lifetime remain unchanged. The archived `UpTimeMs` and `HideTimeMs` fields are interpreted as 800-ms emergence, idle grace and retraction intervals, with partial transitions reversing continuously.

The shared SC1 reader now retains the child blend byte that follows each child ID. The format and numeric modes are documented by [SupercellFlash MovieClip loading](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/display_object/MovieClip.cpp) and [DisplayObjectInstance::BlendMode](https://github.com/sc-workshop/SupercellFlash/blob/main/supercell-flash/source/flash/display_object/MovieClip.h). Imported effect parts preserve normal (0), multiply (3), screen (4) and additive (8) modes. Child normal mode inherits its parent mode while flattening. The renderer retains display-list order with separate material groups per texture and blend. Multiply/screen use premultiplied source alpha so transparent edges remain neutral; additive fire, sparks and glow no longer darken the arena. These per-part GPU operations reconstruct the source modes; nested offscreen group isolation and cross-batch transparency sorting remain approximations. Other asset bundles have not been regenerated with blend metadata.

`reference/client/particle-physics-static-probe.json` retains 14 full assembly ranges, constants, addresses, binary hash and limitations from the pinned 1.8.0 x86 client. REA/Hopper returned unreadable output; the recorded evidence comes from ordinary static `objdump`, with no REA Evidence IDs and no native execution. The owned REA session reports closed; its private temporary directory was retained because cleanup lacked an acknowledgement.

The native particle helper at `0x7b554` subtracts `Inertia × elapsedSeconds` from horizontal speed, clamps that speed to zero, and advances height using half the current-age gravity term. Start height and sampled vertical speed are scaled by 0.1; source gravity by 0.0001. Nonzero inertia uses 16-ms updates via `0x7b65e`, with age incremented before integration. The browser evaluates the corresponding finite sum directly: horizontal distance stops after linear deceleration, and vertical gravity contributes `G × (t² + t × 0.016) / 4` in its existing source-unit conversion. Zero-inertia particles use the continuous `G × t² / 4` limit; the native variable-frame correction is not reproduced. This replaces the former exponential drag and conventional `G × t² / 2` approximation without storing render history.

Source positions/speeds still use the browser's 30-source-units-per-tile conversion. Static native projection uses `(x × 15, (y − z/2) × 12)` at file defaults, but runtime scale writers and their mapping to this browser arena remain untraced. Ground-layer flattening, floor settling, blank/default normalization and emission distribution remain reconstruction limitations. Impact camera movement is documented in the screen-shake section below.

`reference/client/particle-tail-static-probe.json` retains 22 assembly ranges for tail sampling, dual motion states and the affine transform. `particle-tail-composition-static-probe.json` adds 26 ranges and three vtable records resolving the sprite bounds and parent/child composition. Both identify the same pinned binary and its SHA-256, contain ordinary static disassembly, and record no native execution or REA Evidence IDs.

`ParticleMinTailLength` / `ParticleMaxTailLength` are integer millisecond age offsets. The constructor initializes a second motion state at the same birth position with negative age; it begins integrating when that age reaches zero. Nine of the 37 imported emitters use nonzero ranges: tower fire/smoke, three elixir bursts, Balloon-bomb fire/smoke, Fireball sparks and lava. The browser samples integer delays with a separate cosmetic RNG, preserving all preceding clip, lifetime, emission and motion choices. The original RNG's endpoint distribution remains untraced; browser sampling uses an exclusive upper endpoint.

The native tail branch at `0x7ad38` places the particle origin at the midpoint of the two projected endpoints and applies `rotation(direction) × scale(size × (B + distance) / B, size)`. The child sprite retains its own emission rotation. `B` is the child's rendered **height**, including that rotation and the selected frame's authored transforms, excluding parent particle scale. MovieClip virtual slot `+0x30` resolves through `0x315ad0` to the Y-bounds difference at `0x31a090`; the adjacent slot returns width. The bounds query removes root translation but keeps rotation/scale. Export origins remain intact; a midpoint origin does not mean the visible artwork is recentered. The browser composes the full parent affine before child rotation and reflects the latter for its Y-up geometry. That coordinate reflection also corrects source-directed rotation on particles without tails; ground aspect compensation remains outside the child rotation.

Each browser endpoint evaluates the existing age-based motion independently, with a birth clamp before the delay elapses. This avoids a history buffer and gives the same pose for late events and replay reconstruction. Native code integrates the whole current timestep when delayed age first crosses zero; the browser instead evaluates the exact delayed age. Native bounds are queried before updating the child frame; the browser measures its currently evaluated frame for deterministic seeks. Native bouncing, dynamic projection globals, frame-history-dependent bounds, masks and pixel-alpha-tight bounds are not reproduced. Current tail emitters are all nonground and use neither `FrameFromAngle` nor the later angular-rate overwrite branch. Empty frame bounds retain the midpoint and a finite unstretched transform.

## Native screen-shake investigation

`reference/client/screen-shake-native-probe.json` retains nine Hopper evidence records from the pinned 1.8.0 x86 `libg.so` (SHA-256 `a7eb74c5b72770e39b8dc2c55e452fc11434f3df3efc46fd0ea13d28c1da9309`). `node scripts/probe-screen-shake.mjs /absolute/path/to/libg.so` verifies that hash and regenerates `screen-shake-layout.json` with ELF32 load mappings, the position-independent string reference, float constants, scale pointer and trigonometric import names. This was read-only static analysis; the original executable was not run.

The `ShakeScreen` string at `0x615a48` is referenced through a GOT-relative instruction at `0x1eb3e2`, explaining why the previous direct string-reference probe missed it. The column loader stores its index at GOT+`0x1940`; the effect loader reads the integer into object offset `0x60`, and getter `0x1ebdb4` returns it (evidence IDs `ev_d06c1bf83cfe4971193ed4b9c8514a27c29bcd692d0a911c117132616c9b9be5`, `ev_396d82db9eb2c7895030a94256a49c65b9bb49d6cf0d792e7a3f80927d6b0e93`, `ev_1112650942af51d0adddfa76e283add335c737f9b0b15dacf919a51675637c29`).

The effect constructor at `0x77b7e`, gated by its final flag, multiplies this value by the float 0.001 and calls `0x8bc36`. That function replaces the existing scene timer only if the new value is greater. The update function at `0x8bdb0` clears its two offsets, computes a displacement when both frame delta and timer are positive, then subtracts the frame delta and clamps the timer to zero. This supports a millisecond duration with maximum overlap, rather than additive impulses (evidence IDs `ev_f9d863f9f3044839171e35acdca6370918fc2460c3ef634b2a919d42e345d155`, `ev_965453e326aa3ea4436c5720cc0749587f576d8d4a0f93eab836eb2bfc215134`, `ev_b5caa0c65930fb5c79014e3133d84ddecfda05398948e8d13e0a134aa913f3e3`).

The observed displacement radius is remaining time × 0.5 × a referenced scene factor, whose file-backed value is 12. An integer returned by `0x7c716(10000)` is multiplied by approximately 0.0006283, then passed to the imported `cosf` and `sinf`; the resulting offsets are passed with each child to `0x314fa0`, which stores them in child offsets `0x1c` and `0x20` through `0x314ef0` / `0x314f70`. The three additional records are retained in `screen-shake-offset-probe.json`; downstream transform consumption is not traced. The wrapper calls `0x35c670`, whose complete random-distribution semantics were not examined. No shake duration is added from a row's `Time` in the observed constructor. Runtime writers of the scene factor, all constructor flag callers, native frame cadence and the browser display-unit conversion remain unverified. The browser adaptation is described below.


`screen-shake-scalar-probe.json` retains six additional records tracing the effect scalar read through `0x1e49ea`, `0x351560`, `0x352230`, `0x34e9e0` and the integer-vector accessor. A missing-cell sentinel becomes zero. The original CSV loading/blank normalization was not fully traced. Both King effects place their sole authored `ShakeScreen=2000` on continuation row 1 while row 0 is blank. The browser deliberately retains that unique group value; `screen-shake-manifest.json` records both continuation-row interpretations. This is a documented reconstruction choice, not a claim that the unexecuted client resolves that blank identically. Multiple different values in one group fail import instead of being guessed.

`npm run assets:screen-shake` resolves camera effects from the existing source effect roots, including enemy substitutions, and hashes eight inputs plus its generated data. Fireball uses 0.8 seconds, Zap 0.25, Balloon contact 0.35, Balloon bomb and Princess Tower destruction 1, and King destruction 2. A group's shake starts at effect creation; its particle/sound row `Time` does not delay the group timer. The maximum overlapping remaining duration wins.
